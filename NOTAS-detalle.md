## Kubo App (interfaz del cliente + dentro de Kodi — 2026-10-08)
- **`~/kubo-app/`** (Node, puerto **8896**): UI animada tipo Netflix — hero rotativo 3 títulos (Ken Burns + fadeUp), filas *Continuar viendo* (barras de progreso), *Películas gratis* (18 películas de dominio público del Internet Archive con póster real, `content.json`), *Tus servicios* (28 tiles con color de marca desde `services.json`), *Juegos en la nube*; sheets de detalle, panel **Mi plan** con Pausar/Reanudar/Cancelar (UI lista, se conecta a la API en fase 2), selector de dispositivo, buscador, nav inferior móvil.
- **Dentro de Kodi**: addon **`webinterface.kubo`** (en el repo Kubo) = la MISMA UI + un **shim que reemplaza `fetch('/api/…')` por JSON-RPC directo** (`Addons.ExecuteAddon` para abrir servicios/actualizar, `Player.PlayPause`/`Stop`). Se elige en Ajustes → Servicios → Control → Interfaz web = **Kubo UI**; cualquier teléfono abre `http://<ip-de-kodi>:8080/` y controla esa TV. **Verificado en el laptop** (`curl :8080` = 25 KB con content.json).
- **Trampas aprendidas (Kodi addons)**: (1) el manifiesto debe ser `<requires><import addon="xbmc.json" version="6.0.0"/></requires>` + `<extension point="xbmc.webinterface"/>` — con `xbmc.webinterface` como dependencia Kodi lo marca **incompatible (disabledReason=2)**; (2) al reemplazar archivos de un addon, Kodi lo **deshabilita** (hay que habilitarlo + reiniciar); (3) si el addon queda inválido al arrancar, `services.webskin` **revierte solo** a `webinterface.default`; (4) en Android el webserver solo responde con **Kodi en primer plano** (con la cortinilla de notificaciones o pantalla bloqueada, `:8080` no contesta).

- **Top-bar glitch over YouTube/Chromium — FIXED 2026-10-07**: hovering the auto-hidden top bar (`hidetopbar` v126) over a maximized/fullscreen Chromium slid it in and then it vanished/flickered. Root cause: **Mutter unredirect / direct scanout** — the compositor lets a single-surface Wayland client (Chrome/Ozone, Brave, Electron, mpv) paint straight to the display, so the panel is drawn once and then painted over (upstream `hidetopbar#372`, open since 2022; NOT the extension's fault, NOT i915 PSR — `i915.enable_psr=0` was already applied). Fix: extension **`unredirect@vaina.lt`** ("Disable unredirect fullscreen windows", MIT, ~20 lines, monkey-patches `global.compositor.enable_unredirect`) → installed, **ACTIVE**, persisted in `org.gnome.shell enabled-extensions`. No perceptible desktop/video cost; for gaming toggle off (`gnome-extensions disable unredirect@vaina.lt`). RHEL GNOME 49 quirks learned: the extensions D-Bus API is a **proxy** (`gjs -m /usr/share/gnome-shell/org.gnome.Shell.Extensions`) forwarding to the manager **inside the running shell**; `ReloadExtension` is deprecated ("does not work"); a hand-copied extension is invisible to the shell — to register it live call the shell directly: `gdbus call --session --dest org.gnome.Shell --object-path /org/gnome/Shell --method org.gnome.Shell.Extensions.InstallRemoteExtension <uuid>` (registers the on-disk ext and enables it; its EGO-zip unpack skips existing files, so local metadata survives).
